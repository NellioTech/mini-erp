# ERP 庫存管理系統（PWA + SQL Server）

Repo：https://github.com/NellioTech/mini-erp ・ 版本：[v0.1.0](https://github.com/NellioTech/mini-erp/releases/tag/v0.1.0)

SD 訂單 / MM 採購 / IM 庫存 / PP 生產 四模組。
設計原則：**極大化 SQL Server、極少化前端**——能用 T-SQL 物件解決的一律放在資料庫；
Node 只轉呼叫 `api_*` 預存程序，前端只依 SQL 回傳的中繼資料產生畫面，並負責斷線重傳。

## 快速開始
```bash
npm install
cp .env.example .env      # 填入資料庫帳密
npm run db                # 建立資料庫與所有物件（可重複執行）
npm run seed              # 建立示範資料並跑驗證（僅空資料庫）
npm start                 # http://localhost:3000
npm test                  # 對目前資料逐條檢查驗證準則（sp_驗證）
npm run db:reset          # ⚠ 刪除整個資料庫後重建
```

## 架構
```
手機/瀏覽器 (PWA)  ──GET/POST /api/api_*──▶  server.js（薄轉接）  ──EXEC──▶  SQL Server
  app.js：依定義畫畫面                                                   資料表 + CHECK/FK
  sw.js ：離線快取                                                       觸發程序：過帳、庫存帳
  待傳佇列：斷線重傳                                                     視圖/函數：報表、樞紐
                                                                          api_* 預存程序：CRUD、編號
```

## 資料庫物件（db/）
| 檔案 | 內容 |
|---|---|
| 01_tables.sql | 資料表、主鍵、外鍵、CHECK（超出貨/超收/超領、每日庫存餘額公式） |
| 02_views.sql  | 系統欄位/系統參數（畫面中繼資料）、庫存異動來源、報表視圖、樞紐函數 |
| 03_triggers.sql | 過帳機制、庫存異動明細、每日庫存餘額、負庫存檢查、工單 BOM 展開 |
| 04_menu.sql   | 功能表（主選單）與唯讀欄位設定 |
| 05_api.sql    | api_功能表 / 功能定義 / 查詢 / 選項 / 儲存 / 刪除 |
| 06_verify.sql | sp_驗證：驗證準則逐條檢查 |

## 過帳機制（觸發程序）
| 來源明細異動（新增/修改/刪除） | 累加鍵 | 回寫 |
|---|---|---|
| 訂單出貨明細.出貨數量 | 訂單編號+訂單項次 | 客戶訂單明細.出貨數量 |
| 出貨退回明細.退回數量 | 訂單編號+訂單項次 | 客戶訂單明細.退回數量 |
| 採購收貨明細.收貨數量 | 採購編號+採購項次 | 廠商採購明細.收貨數量 |
| 收貨退回明細.退回數量 | 採購編號+採購項次 | 廠商採購明細.退回數量 |
| 工單入庫明細.入庫數量 | 工單編號 | 生產工單主檔.入庫數量 |
| 工單領料明細.領料數量 | 工單編號+物料編號 | 生產工單明細.已領用量 |

以上 8 種單據同時寫入 `庫存異動明細`，並重算 `每日庫存餘額`（期初 + 本期入庫 − 本期出庫 = 期末），期末為負即拒絕。

## 報表
- 已訂未出明細、已採未交明細、庫存在途明細、每日供需餘額：視圖
- 訂單出退分析 / 採購收退分析：樞紐函數 `訂單出退樞紐(@年度)` / `採購收退樞紐(@年度)`，縱軸客戶/廠商、橫軸 01–12 月，統計 出貨+退回 / 收貨+退回
- 庫存異動明細、每日庫存餘額：資料表（觸發程序維護）

## 與原規格的差異
1. `生產工單主檔` 新增 `物料編號`（生產品項）：BOM 展開與入庫比對需要。
2. `銷售組織維護`、`採購組織維護` 新增選填 `工廠代碼`：訂單需求、採購供給要歸屬工廠，才能算「每日供需餘額」（物料+工廠）。未設定者顯示為「(未指定)」。
3. `庫存在途明細`、`每日供需餘額` 以視圖實作（永遠即時、無需同步）。

## 斷線重傳
每筆寫入在手機端產生唯一「請求編號」存入待傳佇列（localStorage），連線恢復或每 15 秒自動重傳；
SQL 端以 `同步請求紀錄` 去重，同一請求編號只執行一次——回應遺失後重傳也不會重複入帳。
被 SQL 拒絕（商業規則）的請求不重傳，顯示於右上角「待傳送」頁。
